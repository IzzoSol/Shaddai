## Per-fix notes / decisions

1. **Skinning guard.** `world-perf-guard.js`: `guardSkin` and the `applyBoneTransform` raycast wrapper no longer skip `__skinClean` meshes. Rationale recorded in-code: the guard only *reads* indices per-component (interleaved-safe) and pins bounds on genuinely bad skins; the Nov-7 explosion came from `_repairSkins` *writing* interleaved data, and that repair still skips the clean files in world-main (untouched). `world-main.js`: new `_skinSanity(root)` (skeleton present, no undefined bone slots, max skinIndex component < bone count, per-component reads); `_nextAgentBody` runs it after the first `mixer.update(0.001)` (bind pose for clip-less bodies) — on failure the body is removed, `_agentBodies[code]`/`entry.body`/`entry._mixer` cleared, and the portrait sprite/beam/frame standee simply stays up (the same fallback as a failed GLB load). `cloneSkinned`'s existing bad-clone detection now also trips on out-of-range skin indices, routing such clones to its position re-link.
2. **Error dedupe.** In the HTML banner script: counts kept in `Object.create(null)` maps; first occurrence appends one `<span>` line to `#errMsg`, repeats only rewrite that line's `(×N)` counter. Counts exposed as `window.__errCounts` (probe hook). WebGL promotion behaviour unchanged.
3. **Emissive clamp.** `setPlayerCharacter`: the `emissiveIntensity = 3.0; color.setRGB(3,3,3)` re-raise for textured bodies is gone (emissive white + `emissiveMap = map` fallback kept; the 0.3 clamp that already ran earlier in the same loop now stands, and is re-asserted in the branch). `_loadHero`: its traverse now applies the same 0.3 clamp (previously no material treatment at all). **Interior resident-agent display path identified as `world-colosseum.js` `loadAgents()`** — the council bodies displayed inside the Colosseum as vendors/ushers/greeter: `lam()` carried `emissiveIntensity` through verbatim (3.0 from `agentBodyFix`); clamped to 0.3 at the conversion site (kit/architecture parts through `lam()` elsewhere are untouched). Checked and left alone: `world-interiors.js` already hard-caps its own materials at 0.50; interior staff bots (`world-interior-agents.js`) use `/assets/kits/` GLBs, which `agentBodyFix` never forces to 3.0.
4. **Warm-up + hero chain.** Precondition verified before changing the cap: `bgCompile` exists (world-main.js ~L535) — an interval that, once `window.__loadPlayable`, re-runs `renderer.compileAsync` every 2.5 s up to 36 times (`?bgcompile=0` opts out). Cap default is now `6000` for every platform (`?warmcap=` override intact; `?precompile=0` is now a no-op alias of the default). Hero chain: new `_defaultHeroFile()` (= `WorldOperatives.glbFor(WorldOperatives.defaultCode())`, fallback `/assets/agents/SHADDAI.glb`); the boot safety-net (22 s) and the `setPlayerCharacter` failure fallback now start there; `_loadHero`'s error handler falls back to it once, then leaves the capsule. `hero-walk.glb`/`robot.glb` are never requested.
5. **Dismount resync.** Unlocked branch (~was L6112): before stepping, `_cpU = _pctl.getPos()`; if XZ Manhattan divergence from `playerPos` > 1e-3 (the locked branch's own threshold), `_pctl.setPos(playerPos.x, playerPos.y, playerPos.z)`. Pointer-locked branch unchanged.
6. **Respawn Y.** `world-survival.js`: new `groundY(x,z)` reads the host sampler via the same `__w3dDebug` hook family `pp()` already uses (`__w3dDebug.terrain.heightAt`, set by world-main for both v4 and legacy terrain; `.terrainV4` as fallback). `respawn()`: spot's own `y` wins; else `p.y = groundY + 0.1`; no sampler → old behaviour (y untouched, fail-soft). `world-main.js` fallback death path (dragon-kill, ~L4222): `playerPos.y = heightAt(Central) + 0.1`. **'bazaar' station entry NOT added** — stations in `world-layout.js` are build instructions, not pure data: `world-transit.js` builds a physical platform + spokes + a ride destination for *every* `WORLD_LAYOUT.stations` entry, so adding one is a world-content change outside this fix's scope. The existing hardcoded fallback `[-100, 100]` already matches `BAZAAR.pos` (−100, 0, 100) exactly, so `bazaar()` resolves to the right spot today.
7. **Mobile cuts.** Cut 1 exactly per MOBILE_PASS2_PLAN: the four builders (`WorldTransitKit.dress`, `WorldRealmKits.build`, `buildWorldTownsfolk`, `WorldRealmDress.build`, call bodies byte-identical) wrapped in `_dress()`; `_MOBILE_LITE` parks it as `window.__mobileDress`, desktop runs it in place; `_afterSpawn` runs and clears it once when its gate opens.
