Set up Claude Desktop

  1. Open the config file. In Claude Desktop: Settings → Developer → Edit Config. That opens claude_desktop_config.json — on Windows it lives in %APPDATA%\Claude\, on macOS in ~/Library/Application Support/Claude/.

  2. Paste this in. If the file already has a mcpServers block, add the shaddai entry inside it rather than replacing the whole file.

    claude_desktop_config.json 
    loading the real path from the server…

  3. Restart Claude Desktop — fully quit it, not just close the window. The server is started by Claude itself, so it has to relaunch to pick it up.

  4. Check it took. Ask your Claude list the SHADDAI agents. If it answers with the seven and their document counts, you are connected.

Claude Code & Cursor

  1. Claude Code — one command, run from anywhere:

    terminal 
    loading…

    Then /mcp inside Claude Code lists the tools it picked up.

  2. Cursor — same JSON, different file: ~/.cursor/mcp.json for every project, or .cursor/mcp.json inside one project. Paste the identical mcpServers block, then reload Cursor.

If it does not connect

  1. Node has to be on the PATH. Claude Desktop launches node itself. Run node -v in a terminal first; if that fails, install Node and restart.

  2. Use the full path, no shortcuts. On Windows the backslashes must be doubled in JSON, exactly as they appear in the block above. ~ is not expanded.

  3. Test the bridge on its own: node mcp-server-rag.js --self-test from the backend folder. It handshakes with itself and reports which tools answered.

MCP is an open protocol — nothing here locks you to one assistant. The same server works with any MCP client that can launch a local process.
