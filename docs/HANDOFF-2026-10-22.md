### 2.2 The RAG brain — it answers now
Your complaint was exact: it was *"not just excerpts but real knowledge"* and it was returning *"random useless information"*. It is now measured, diagnosed and fixed.

| Metric | Before | After |
|---|---|---|
| **precision@1** | **7%** | **100%** |
| precision@3 | 53% | **100%** |
| **answer coverage** | 27% | **100%** |
| **off-topic rate** | **93%** | **0%** |
| **junk density** | *unmeasurable* | **0%** |
| abstention | 0% | **50%** |

**The measurement** — `backend/scripts/rag-audit.mjs`, 21 probes (19 in-corpus, 2 must-abstain... now 17 + 4). Baseline and result: `docs/rag-audit-baseline.json`, `docs/rag-audit-after.json`.

**The four structural defects:**
1. **The chunker sliced on WHITESPACE** into 500-word windows — every chunk began and ended mid-sentence. That *was* the excerpt problem. Now it packs **whole sentences**.
2. **The stored text was raw speech.** Chunks carried `&gt;` as a term; `gt` scored **0.56** in one of the worst vectors — the single largest weight in it. Now `decodeEntities()` (always safe) + `cleanSpoken()` (filler, doubled words, punctuation), and `cleanSpoken` applies **only to spoken docs** so prose is never touched. The 91k existing chunks are cleaned at the **output boundary** in `brain-server.js`, so they read well now without the 890 MB rebuild.
3. **A score cannot tell an answer from a coincidence.** The relevance gate now uses **coverage**, and the coverage is **IDF-weighted** — a rare term (*n8n*, *1994*, *Reykjavik*) counts far more than a generic one (*skills*, *workflow*).
4. **There was no platform knowledge at all.** The corpus is spoken-video transcripts with no authoritative statement of our own rules — so a business course that happened to say "revenue" won by default. Now **tier 1** is four authored documents **generated from `prices.json` and `catalog/catalog.json`** (so they cannot drift): the economy · the registry and every price · how a bot gets in · the agent lifecycle, job market and council. A platform question is answered from them **directly** — exact, cited, **no LLM in the loop**.

**Three bugs in my own audit**, because a measurement that lies is worse than no measurement: it read only the first **90 characters** of a result (the title, not the text); it passed `query` where `rag_ask` wants `question`; and its abstention regex looked for *"not in the brain"* — a phrase the brain never uses (it says *"no strong knowledge"*), which was hiding the whole abstention fix.

### 10.3 The thing that nearly broke the product — and why it didn't
A first pass added frontmatter to **every** note, including the 5,321 `SKILL.md` files.
That would have broken the live product:

- `backend/skills-loader.js` reads `SKILL.md` **live from this vault at runtime**.
- Its `parseFrontmatter()` matches the **first** `---` pair and reads `name:` /
  `description:` from it. A block without those keys **silently blanks the skill's
  name and description for every bot on the network**.
- `backend/scripts/build-skills-catalog.js` bakes the same files into the shipped catalog.

**What was done:**
1. All **5,321** `SKILL.md` files restored **byte-for-byte** from a pre-change backup.
   Verified: **346 checked, 0 mismatched**, 0 still carrying our marker.
2. The live loader was run as the proof: **5,321 skills loaded, 0 unnamed, 0 without a
   description**, and `getSkillContent()` returns the original text.
3. **Every one of the 641 pre-existing notes byte-verified against the backup:
   0 body bytes changed.**
4. **File mtimes restored** afterwards — tagging a file updates its mtime, which would
   have made "newest first" a lie.
5. **Credential notes indexed but never rewritten.** Not one byte of a file holding a
   live key was touched.
